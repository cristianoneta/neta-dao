# Individual Juno governance votes

Cosmoot retains native Juno voting periods already open on 5 November 2026 (#387 and #388) and all voting periods that start after the cutover. It reads the existing local block history for those open votes. Earlier completed proposals keep their official final tally. DAO DAO contract ballots and validator bonus scoring use their existing separate paths.

The main collector resumes from a block/hash checkpoint, validates contiguous blocks and event checksums, accepts only successful transaction events captured by the history service, and applies the final accepted weighted ballot for each voting address. Transaction and event order include the closing block. SDK v0.53 expedited-to-regular conversion starts a fresh ballot set. A missing voting start is displayed as partial. Counts are distinct direct voting addresses, including zero-power voters. The count after a decision filter includes every address with a positive share for that decision.

The permanent SQLite ledger is kept in the collector archive, outside rolling block retention. The pending export and cursor can be retried independently. Per-proposal JSON under the public data tree is included in successive snapshot generations and the existing locked infrastructure backups. Publication rejects missing previously published proposal files. Both Sites use the existing same-origin read proxy and its fixed public origin. Offline origin and missing record have distinct responses.

Opening a proposal shows live participation during voting and saved observations after closure. The optional second calculation reads staking state at the recorded height/hash and reconciles all four totals with native governance. A different-height or unavailable response leaves individual ballots intact. An earlier saved power sample is explicitly labeled with its own block and time. The official final tally is read separately. Public archive data serves display only.

Deployment requires the existing website release and updated main collector/publisher sources. Verify an open proposal's ID, block, distinct addresses and weighted choices at the same height. After voting ends, verify the closing-block record, official final tally, search/filter behavior and persistence across subsequent publication and backup. Do not infer a completed mainnet acceptance test from fixtures.
