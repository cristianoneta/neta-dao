Sources & details

After the v31 upgrade at height 42,452,000, this page uses signatures included in the last five confirmed blocks (one block behind each node’s tip). “Signed” means at least one block signature in this window; the latest block’s voting power is shown separately. Signatures across blocks are never added to claim a consensus quorum. A committed block requires more than two thirds of voting power for that block.

First participation evidence uses the earliest saved consensus vote or canonical block signature. The ≤ delay and “By” time are upper bounds: the validator was participating by then, but may have been ready earlier. Source labels distinguish pre-restart votes from block signatures; a first signature after restart does not by itself prove an upgrade after restart. A nil vote proves participation but is not agreement on a block. Vote times are reported by validators; capture times and coverage gaps remain in the archive. This measures observed consensus participation, not binary installation or an exact readiness ranking. For v31 only the recovered 09:32 Berlin snapshot survives; absence there is not proof of being unready.

First-signature delay uses each validator’s first included precommit timestamp after the upgrade halt. It includes the shared network halt. The block offset shows how many blocks after the first resumed block it appeared. These observations cannot reconstruct earlier readiness or actual software-upgrade duration; validator clocks and commit inclusion can differ.

A missing block signature may be a missed block or a signature not included in the commit; it does not establish a failed upgrade. Nil votes do not count as block signatures. At a validator-set change, the window shortens to the matching set. Before confirmed post-upgrade history is available, current-round votes are shown explicitly. Observations are RPC reports, not an independent cryptographic or software-version audit.
